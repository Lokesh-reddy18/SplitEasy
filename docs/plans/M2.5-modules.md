# Milestone 2.5 — Split into modules

Requested after M2: move features into separate modules so they build independently, before M4 adds Firebase. Behaviour is unchanged and the UI pattern (MVVM with one-way state) is left as it is.

## Module map

```
:app ──► :feature:home ─┐
     ├─► :feature:group  │
     ├─► :feature:expense├─► :core:designsystem ─► :core:domain
     ├─► :feature:settle │   :core:data ─────────► :core:domain
     └─► :feature:profile┘        └──► :core:database ─► :core:domain
                           (tests) :core:testing ─► :core:domain
```

| Module | Type | Contents |
| --- | --- | --- |
| `:app` | Android app | `MainActivity`, `SplitEasyApp` (Hilt), `MainViewModel`, navigation routes, bottom bar |
| `:core:domain` | Kotlin/JVM | Models, money, split, balance, settlement, group/expense rules, UPI link + result, repository interfaces, use cases, feature flags |
| `:core:database` | Android library | Room database, entities, DAOs, migrations, exported schemas; test fixtures shared with `:core:data` |
| `:core:data` | Android library | Repositories, mappers, DataStore preferences, current user, sync scheduler, demo data, Hilt bindings |
| `:core:designsystem` | Android library | Theme, colours, type, shared components, date/amount formatting, UPI ID sheet, all strings, icons and the font |
| `:core:testing` | Kotlin/JVM | Fake repositories, model fixtures, Coorg trip test data, `MainDispatcherRule` |
| `:feature:home` | Android library | Groups home, New group, group picker, Archived groups |
| `:feature:group` | Android library | Group detail and feed, Group settings |
| `:feature:expense` | Android library | Add/edit expense, Expense detail |
| `:feature:settle` | Android library | Balances, Settle up |
| `:feature:profile` | Android library | Profile |

Convention plugins in `build-logic/convention`: `spliteasy.jvm.library`, `spliteasy.android.library`, `spliteasy.android.compose`, `spliteasy.android.feature`.

## Decisions
- **Features don't depend on each other.** The only shared screen helper (`IndianGroupingTransformation`, used by both Add expense and Settle up) moved to `:core:designsystem`.
- **One resource home.** All strings, icons and the font live in `:core:designsystem` (`com.split.easy.core.designsystem.R`). The app keeps only the launcher icon and window theme. `:app` lint uses `checkDependencies` so icons used in features aren't reported as unused.
- **Profile no longer reads `BuildConfig`.** The app passes `isDebugBuild` and `appVersion` in, so the feature doesn't depend on the app.
- **`:core:domain` is plain Kotlin**, so the "no Android imports in domain" rule is now enforced by the build, and its tests run without Android.
- **Coverage gate** (90% on money/split/balance/settlement/UPI) moved to `:core:domain`.
- **Package names are unchanged** (`com.split.easy.ui.home`, etc.), so the diff is mostly file moves.

## Outcome
- `./gradlew ktlintCheck lint test koverVerify assembleDebug` passes: 217 tests, 0 lint errors in every module, domain coverage 100%.
- **Rebuild after editing one screen:** 3–6 s before, 4–6 s after. At this size Gradle was already reusing most work in a single module, and each module adds a little overhead. Gains should grow with M4/M5 code; the main benefits today are enforced boundaries and parallel builds of independent modules.
